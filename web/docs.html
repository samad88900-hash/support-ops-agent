Support & Ops Agent API

Version 1.0.0 · JSON over HTTPS · Bearer token required for /v1/*

Machine-readable spec: /openapi.json

Authentication

Set API_ACCESS_KEY on the server, then send it on every /v1 request:

Authorization: Bearer YOUR_API_ACCESS_KEY

Missing or invalid keys return 401. If the server has no key configured, /v1 returns 503.

POST /v1/chat

FieldTypeNotes
messagestringRequired, max 4000 chars
historyarrayOptional, max 20 {role, content} messages
sessionIdstringOptional, max 64 chars
curl -X POST https://YOUR_HOST/v1/chat \
  -H "Authorization: Bearer YOUR_API_ACCESS_KEY" \
  -H "Content-Type: application/json" \
  -d '{"message":"Where is order ORD-1042?"}'

Response includes answer, intent, citations, tools, trace and meta (mode, latency, cost, guardrails, requestId).

GET /v1/agent

Machine-readable capabilities, tool list and approval limit.

GET /v1/health

Authenticated liveness check.

GET /healthz

Public liveness/readiness probe for uptime monitors and load balancers.

Limits & errors

  • Rate limit: RATE_LIMIT_PER_MIN requests per IP per minute (default 60). Exceeding it returns 429 with Retry-After.
  • Every response carries X-Request-ID. Send your own header to correlate logs.
  • Refunds above REFUND_APPROVAL_LIMIT are never drafted — the agent escalates to a human instead.
